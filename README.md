# Code Quality of LLM-Generated Python Code

Artifacts for the bachelor thesis *Can Iterative Static-Analysis Feedback Improve
Maintainability Without Reducing Functional Correctness?*

Amirhossein Rahimnazari · B.Sc. Computer Science dual · Hochschule Darmstadt
Academic supervisor: Prof. Dr. Markus Döhring · Industry supervisor: Arndt Völkle

The submitted thesis is `paper.pdf`.

---

## What this repository is for

Every number in the thesis is derived from the files in `Project/`. This repository
exists so that claim can be checked rather than taken on trust: all 1260 generated
solutions are retained together with the measurements recorded for them, and the
analysis can be re-run offline — **no model, no network and no API key required.**

## Verifying the results in three commands

```bash
cd Project
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

.venv/bin/python src/verify_artifacts.py   # re-measures all 1260 archived solutions
.venv/bin/python src/verify_oracle.py      # validates the correctness oracle itself
.venv/bin/python src/stats.py              # reproduces every p-value in the thesis
```

Expected output:

| Script | Reproduces |
|---|---|
| `verify_artifacts.py` | 1260 of 1260 records re-measure to their recorded values |
| `verify_oracle.py` | 63/63 reference solutions pass; 63/63 corrupted variants fail |
| `stats.py` | Table 2 and Table 4 — all medians, p-values and Bonferroni markings |
| `supp_metrics.py` | Table 3 (supplementary metrics) |
| `compare_blind.py` | §4.9, the code-blind ablation |
| `plots.py` | The four figures in `figures/` |

Tool versions are pinned in `Project/requirements.txt` because `radon` and
`complexipy` have both changed their scoring across releases. The model is pinned
by digest in `Project/config.json`.

## Re-running generation (optional — not needed to verify the results)

Everything above runs offline. Only re-running the loop itself needs a model.

**1. Install Ollama** — <https://ollama.com/download>. The experiment used client
version **0.30.10**. Start the server before running anything (`ollama serve`, or
`brew services start ollama` on macOS); the runners talk to `localhost:11434`.

**2. Pull the model:**

```bash
ollama pull qwen2.5-coder:7b     # ~4.7 GB, Q4_K_M
```

**3. Check you got the same weights.** An Ollama tag names a model rather than
fixing its content, so a fresh pull is not guaranteed to resolve to the weights used
here. Compare against the digests recorded in `Project/config.json`:

```bash
ollama list    # expect ID dae161e27b0e for qwen2.5-coder:7b
```

| Recorded in `config.json` | Value |
|---|---|
| Model tag | `qwen2.5-coder:7b` (Q4_K_M) |
| `ollama list` ID | `dae161e27b0e` |
| Weights layer digest | `sha256:60e05f21…` |
| Weights size | 4,683,074,048 bytes (4.68 GB) |
| Sampling | temperature 0, seed 42, `num_ctx` 4096, 3 iterations |

If your digest differs, the registry has re-tagged the model since June 2026, and
regenerated trajectories are not directly comparable to the archived ones.

**4. Run a loop** — for example `.venv/bin/python src/run_guarded.py`. The archived
runs in `results/` and `generated/` are what the thesis reports; a fresh run writes
alongside them.

## Two things to know before reading the data

**Five of the eight result files are canonical.** `Project/results/README.md` states
which. Two runs were superseded after an integrity audit found that two loop runners
had written their generated code to the same filename pattern, so the second
overwrote the first. The affected configurations were re-run under collision-free
names, and a previously recorded Maintainability-Index effect did not reproduce; it
was withdrawn. This is disclosed in §5.5 of the thesis. The superseded files and the
scripts that read them are kept deliberately, so that the disclosure can be verified
rather than believed — those scripts print a warning banner before their output.

**Recomputation is exact; re-running generation is not.** Re-measuring the archived
solutions reproduces every recorded value exactly. Re-running the loop will not
reproduce the trajectories: single-shot generation is deterministic under greedy
decoding with a fixed seed, but once any intermediate iteration differs, the
following ones can diverge. §3.7 and §5.5 develop this distinction; it is why the
thesis rests its conclusions on effect direction and significance rather than on
exact magnitudes.

## Use of AI tools

Disclosed in full in the thesis (*Declaration on the Use of AI Tools*). In short: the
LLM under study generates and refactors the measured solutions, which is the
experiment itself; AI assistance was separately used for prose, code, LaTeX and
literature search. The research question, design, hypotheses and conclusions are the
author's own, and every reported measurement comes from the analysis pipeline in
`Project/src/`.
